These are the books that stuck with me. Some are thick references you dip into for years, others you can finish in a few weeks. I've grouped them by what they teach, with a note on who should pick each one up.

## Foundations

### [Introduction to Algorithms](https://a.co/d/0aUi9R5O)

_Cormen, Leiserson, Rivest, Stein_

The standard algorithms reference, usually called CLRS. It covers sorting, graphs, dynamic programming, and complexity analysis with full proofs. Don't read it cover to cover. Pick a chapter when a problem calls for it, and work through the exercises.

**For:** anyone preparing for technical interviews or grinding LeetCode who wants to understand _why_ a solution works.

### [Database Systems: Design, Implementation, & Management](https://a.co/d/01xzMNTd)

_Coronel, Morris_

A thorough tour of relational databases: data modeling, ER diagrams, normalization, SQL, and transactions. It teaches you to design a schema before you write a single query.

**For:** developers who use databases every day but never learned the theory behind them.

## Languages

### [JavaScript: The Definitive Guide](https://a.co/d/08MndFO6)

_David Flanagan_

A complete reference for modern JavaScript, from the type system to modules, iterators, and async code. It explains how the language actually behaves, not just how to use it.

**For:** web developers who learned JavaScript by copying examples and want to fill the gaps.

### [Programming Rust](https://a.co/d/02w5wcJm)

_Blandy, Orendorff, Tindall_

A deep introduction to Rust that spends real time on ownership, borrowing, and lifetimes, then covers traits, generics, and concurrency in depth.

**For:** programmers coming from C, C++, or a garbage-collected language who want to write Rust with confidence.

### [The C++ Programming Language](https://a.co/d/0dxsdEOM)

_Bjarne Stroustrup_

The language's creator explains C++ in depth, including why it was designed the way it is. It's a reference, not a tutorial, and it's long.

**For:** people who already write some C++ and want the complete picture.

## Tools

### [The Software Developer's Guide to Linux](https://a.co/d/0iuyTNt5)

_David Cohen, Christian Sturm_

A practical guide to the command line for developers: the shell, processes, permissions, networking, and the tools you reach for when something breaks on a server.

**For:** developers who want to be comfortable in a terminal. A good first step before daily-driving Linux.
